# Quant Pilot · OKX 模擬自動交易終端

公開展示與最新回測：[Quant Pilot](https://alex870715.github.io/sideproject/quant-pilot.html) · [雲端部署說明](CLOUD.md)

## 啟動新版整合工作台

```bash
.venv/bin/python main.py --autopilot --port 8812
# 或 .venv/bin/python -m webui.autopilot_server
```

開啟 http://127.0.0.1:8812 。使用既有 `.env` 的 Demo 金鑰，必須明確設定 `OKX_DEMO=true`；環境不是 Demo 時拒絕交易。金鑰只留在後端。

### 操作

- **OKX 模擬資產**：直接讀取交易帳戶全部幣別、OKX 的 USD 總權益估值、每幣可用／凍結餘額、全部持倉與一般／OCO／條件委託。標示本機器人及其他部位，顯示擷取時間；失敗時保留上次資料並標記待更新。USD 估值不是可用 USDT，其他帳戶資產不併入此總額。
- **交易總覽**：策略權益、含費用淨損益、今日損益、剩餘回撤額度、即時市場狀態及持倉。
- **啟動機器人**：開始依規則選擇訊號並送 OKX 模擬委託。首次安裝預設暫停；之後重啟保留原啟用狀態並先同步帳務。
- **暫停進場**：不開新倉，既有持倉仍繼續管理。
- **停止並平倉**：關閉自己建立的部位，透過 reduce-only 防止反向開倉，等待交易所確認。
- **帳戶資金配置**：可用 USDT 的 25%／50%／75%／全部快選，只填入預算，需儲存後才生效。不同幣別不自動兌換，交易中仍禁止改預算；機器人持倉保證金以 OKX 回報顯示。
- **機器人設定**：最低 20 USDT、無固定上限的預算與 1–20 倍逐倉槓桿、保守／均衡／積極、短／中／長／自動週期，以及允許做空。啟用中或仍有持倉／待確認委託時不可改設定；暫停且空倉後可調整本金，資金增減不算獲利；報酬率以每次資金調整切段串接，保留原損益、當日損益及回撤，已觸發的風控不重置。
- **回測實驗室**：單週期、BTC／ETH／SOL 共用可設定的本金與槓桿，同一份訊號和部位規則，含費用、滑價、歷史資金費率與後段 30% 驗證。結果、參數、來源資料指紋可匯出。
- **決策與紀錄**：開關、進出場、略過原因、交易所確認、已結算損益。

### 目前規則與限制

預設均衡：單筆風險預算 0.75%、保證金與估算成本額度 65%、每日虧損停止門檻 3%、從策略高點回撤停止門檻 8%、每日最多 6 次送出進場。預設 **100 USDT、1 倍逐倉、最多 1 個部位**；槓桿可設 1–20 倍。每日以台灣時間為界，累計回撤停止不自動重置。

本金不設產品固定上限；啟動仍受帳戶可用 USDT 限制，下單受交易所張數、槓桿及部位級距限制。槓桿不會自動放大停損風險：部位取「風險預算 ÷ 含成本停損距離」與「保證金額度 ÷ 每單位保證金及成本」較小者，所需保證金為名目金額 ÷ 槓桿。下單前先設定並確認交易所回傳的逐倉槓桿，成交後按該筆委託保存的槓桿核對，不依目前偏好猜測。

進場要求停損距離與雙邊成本不超過初始保證金的 70%，作為保守緩衝；成交後檢查 OKX `liqPx`，若停損在預估強平价之外即嘗試減倉平倉。此緩衝不等於精確的強平模型，`liqPx` 會隨費用與市場變化，高槓桿回測未模擬維持保證金級距或強平。

黑底交易終端提供槓桿滑桿與 1／3／5／10／20× 快選，即時預覽保證金、理論名目上限、單筆風險及每日停止門檻。設定中的高槓桿使用黃色提示；回測本金與倍率獨立設定，舊版回測紀錄仍以 100 USDT／1× 顯示。

三種打法：趨勢回踩、量能突破、盤整回歸；允許順勢做多／做空。15m 最長 8 小時、1H 最長 2 天、4H 最長 7 天。自動模式同時檢查三個週期，按規則優先級挑選訊號，**不是預測最佳收益，也不是已訓練的自我學習模型**。

預算只用自己建立的部位淨損益，不以帳戶 totalEq 或其他幣種估值擴大下單。最小合約張數採向下取整，無法符合預算就略過。進場同時附交易所標記價格停損與止盈；成交 60 秒後仍無法確認停損，會嘗試平倉。

使用者設定的預算為**軟體資金帳本**，未建立交易所獨立子帳戶。停損與虧損門檻不是保證成交損失，滑價、跳空、交易所異常可能超出估算。避免以同一個帳戶同時執行舊 Pump Bot 或其他程式：偵測到其他持倉／委託會停止新進場，數量或模式被外部操作改變時停止自動操作。此版本限 `net_mode`，不自行更動帳戶持倉模式。

送單前先保存唯一委託識別碼與意圖；寫入請求不自動重試。超時後只查原委託，結果不明時停止新交易，不冒險重送。部位平倉後以 OKX 歷史部位的 realizedPnl、fee、fundingFee 結算，帳務尚未確認則等待。

本機紀錄保存在 `data/autopilot/`，已排除版本控制；請勿在交易中刪除或重置 `state.json`。帳本綁定金鑰指紋，換帳戶不會沿用原紀錄。檔案鎖阻止同時啟動兩個新版服務。

程式需持續執行且電腦保持連線。關閉程式後，已確認的交易所停損／止盈仍有效，掃描與到期出場會中斷。本機沒有設定 OS 開機自啟；雲端常駐可使用 [Render / Docker 部署設定](CLOUD.md)，需獨立的非休眠主機與持久磁碟。

### 回測成立條件

使用 OKX 已收盤歷史永續 K 線、目前合約規格，三幣共用本金；訊號於下一根開盤成交。來回分別計手續費及滑價，各邊預設 5 bps。加入實際歷史結算費率；區間內費率先以該根開盤價格估算，再判斷停損／止盈。買賣成交價 K 線近似標記價格，不模擬委託簿、部分成交、強平與歷史規格變化。**單週期回測不等於跨週期自動模式的完整績效。**

資料不足或有缺口會直接停止，不產生模擬獲利。沒有任何績效保證；看到正回測仍需更多時間與 Demo 成交驗證。

資料規格與損益定義：[OKX V5 API](https://www.okx.com/docs-v5/en/)。

# 既有 Quant Studio 現貨研究與 Pump 控制台

以既有 OKX Pump 交易引擎為基礎，新增繁體中文策略研究、短中長週期、風險設定與可重現回測。

## 先開啟策略工作台（不需要 API Key、不會下單）

```bash
.venv/bin/python -m webui.research_server
```

開啟 http://127.0.0.1:8811/lab 。若尚未安裝環境：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

1. 選擇短線 15m、中線 1H 或長線 4H。切換會更新預設回測天數與持倉上限。
2. 選擇順勢回踩 HigherLow、放量突破、爆量回彈、動能點火。
3. 調整模擬本金、單笔風險預算、資金上限、ATR 停損、R 止盈。進階設定可調整訊號參數與成本。
4. 儲存草稿，或執行回測。檢查淨報酬、收盤權益最大回撤、交易數、後段 30% 驗證、交易明細與操作建議。
5. 在「我的研究紀錄」載入草稿、查看結果，或匯出包含完整設定與交易的 JSON。

資料存於 `data/research/drafts` 與 `data/research/results`。列表顯示最近 50 份；檔案保留。每個服務同時只執行一個回測；執行中的工作不跨重啟恢復，完成結果會保留。

## 回測假設與限制

- 使用 OKX 公開現貨歷史已收盤 K 線（BTC/ETH/SOL-USDT），不需要帳戶金鑰；沒有連線時直接顯示失敗，不捏造行情。
- 最多 18,000 根正式樣本，另外 150 根預熱；缺資料、缺口或覆蓋不足時拒絕產出績效。
- 只做多、無槓桿、一次一個部位；部位取風險預算與資金上限的較小值。
- 收盤訊號於下一根開盤成交。停損/止盈同根觸及採停損優先；停損跳空按較差開盤價格再計滑價；期末強制平倉。
- 雙邊計入手續費、滑價。預設費用是假設值，應依個人費率調整。
- 買入持有基準使用全額本金、未扣費，曝險可能高於策略。
- 後段 30% 重新初始化資金及持倉，只使用此前資料預熱，不自動尋找最佳參數。反覆參考後段調參仍會過度擬合。
- **此為現貨研究模型，不是原 Pump 永續交易引擎的等價回測。** 不模擬資金費率、強平、委託簿、部分成交或合約張數限制，也不將研究草稿自動套用到交易帳戶。
- HigherLow 增加「價格站上向上的趨勢均線」過濾，降低下跌中的回踩訊號。這是待驗證的策略改動，不代表已證明收益提升。

沒有策略可以保證持續獲利。不要把單次正回測當作實盤部署依據。原文件的固定獲利與「適合實單」宣稱已移除。

## 既有 OKX 交易控制台

```bash
# 先依 .env.example 設定環境，確認 OKX_DEMO=true
.venv/bin/python main.py --pump --mode web --port 8810
```

- `/pump`：原有持倉、交易方案、自訂策略與風險控制。
- `/lab`：新增研究工作台，與獨立服務相同。
- 短線方案需 `OKX_BAR=15m`，中線 `OKX_BAR=1H`，長線 `OKX_BAR=4H`，資金費率方案 `OKX_BAR=5m`。方案週期與執行引擎不符時拒絕套用，避免持倉時間失真。
- 新增長線 HigherLow 方案：4H、1 倍逐倉、30 天持倉上限。此方案與研究模型的出場設定需分別檢查。
- 引擎持倉與冷卻時間改按各幣種 K 線時間計算，避免掃描幣種數量放大時間；策略初始化在擷取新 K 線之前，避免重複餵入。

此工作台設計為本機使用。啟動研究服務不會啟動交易引擎。
